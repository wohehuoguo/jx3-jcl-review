# 照夜 · 洛阳战报

在浏览器本地解析 JCL，查看洛阳之战25人普通的点名、实际承伤、死亡和关键机制事件。

作者：坐下来谈谈不@梦江南 with codex

## 使用

- 桌面 Chrome / Edge 点击「连接日志目录」，选择包含多个角色 combat_logs 的上级目录。仅请求只读权限，不要求账号或角色绑定。
- 每15秒递归检查新 .jcl；进行中的 .jcl.log 等到战斗结束改名后再处理。网页关闭后停止。再次访问可以恢复目录授权与本机历史。
- 也可以多选文件、拖入 JCL，或在使用说明中选择「导入文件夹快照」。快照只导入当下文件，不持续扫描。
- 首次进入展示五场明确标注的合成示例。读取自己的文件后切换到本机日志；示例不会写入本机历史。
- 通过战斗列表、首领、结果和日志类型筛选；支持点名与实际承伤核对、逐次死亡详情、关联原始行和 JSON 导出。

## 校验与分析范围

当前白名单使用测试服资料中的地图835，对应25人普通洛阳之战。校验读取日志内部进脱战事件的地图 ID，文件名和实际人数只作参考。地图缺失、冲突或未适配的记录单独标记；不会因有25名玩家或改了文件名就通过。

点名通过 Buff 获得者与事件时间关联；实际名单包含数值伤害、零伤命中和免疫事件。多个圈不能区分归属时保留合并名单。被点但未见命中可能是成功规避、技能中断或记录缺失，不直接判断缺席。不使用预设分组，也不从副本日志虚构全团坐标。

老五的「赤幽快照」按接圈、一式、背面二式、逐次幽影引导与戾煞命中分段，保留全团每个人的赤煞/幽煞层数、隔绝、重伤状态和相对上一张的变化。默认取最后命中后0.5秒内状态，遇到下一机制提前截断；只见施法时取下一机制前。接圈伤害条数不能证明40圈接全。没有基线的未记录层数显示「?」，不自动抵消或补全缺失 Buff。旧版战报重新导入同一份 JCL 可升级，不另存重复记录。

每条死亡关联之前8秒的受击、治疗和 Buff；优先寻找临死1.5秒内与击杀者一致的伤害。已记录机制分支与相邻受击推断分开标记。支持赤幽人数与层数分开统计、戾煞致命/高伤分支、强化落圈、煞气爆发和炸弹减员等证据。首死者不自动等于责任人，正常坦克承伤不自动记为失误。

首领重伤事件用于确认击破；全员重伤后脱战可识别为团灭。其他减员、主动停手或重置可能无法区分，保持结果待确认。

**体验版尚未使用真实洛阳 JCL 做回归校准。** 规则依据2026-10-26核对的测试服技能资料；正式服或新地图 ID 需要更新映射。未知技能保留 ID。字段齐全也不代表客户端事件无遗漏。本页不做官方防篡改认证。

## 本机数据

原始日志在 Web Worker 中解析，不上传服务器，没有 AI API 调用。目录句柄和解析结果保存在当前浏览器 IndexedDB。相同文件内容按 SHA-256 去重；不同记录者的同场日志分别展示。支持 UTF-8、GBK/GB18030；Lua 表使用独立字面量解析器，不执行 Lua 或 JavaScript。单文件上限128MB，每次目录扫描处理最近60份新日志，后续继续处理待解析文件。

## 本地运行与验证

需要 Node.js 20以上及 Python 3。无 npm 依赖，无构建步骤。

    npm test
    npm run dev

打开 http://127.0.0.1:8771/ 。生成本机验收样本可运行 node test/generate-fixtures.mjs，样本写入被忽略的 test-output 目录，全部为合成记录。

测试覆盖递归目录扫描、进行中日志跳过、变更与改名发现、目录授权中断、扫描取消与规模限制，以及 Lua 字面量安全、UTF-8/GBK、内部地图校验、缺人参战、多点名与命中关联、零伤/免疫、无受击点名、赤幽人头统计、重复死亡、战复与损坏日志。
